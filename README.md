# 裝置設計
## 概觀
製作maimai前我們要先理解到他本身有哪些部分:
- 外框，也就是那八顆按鍵，以及按鍵之間的裝飾框
- 內圈，或者說那片"觸碰螢幕"
- 前面板，用來固定外框和內圈，並把整體鎖在支架上
- 支架骨幹，用來支撐前面板以及"顯示面板"
- 電路和韌體，負責接收內外框訊號傳給電腦

## 螢幕和觸碰
我想很多人(好啦至少我以前)會覺得maimai中間就是一塊像手機一樣的觸控螢幕，但不知道大家有沒有發現在機台上面觸控似乎沒那麼靈敏? 打個比方，選歌介面可以左右滑動來快速跳好幾首歌，但似乎要滑的動作要夠大才會有反應

沒錯，maimai的螢幕其實是由前面所說的"顯示面板"和"觸碰螢幕"組成，"顯示面板"其實就是個**43吋的電腦螢幕/電視**，透過直立的方式掛在支架上，從外面機台能看到的分上面和中間螢幕其實都是從這片螢幕上顯示。

那麼"觸碰螢幕"呢? 他是一塊玻璃，上面利用一種透明的導電材料**ITO**，分區塊貼在一塊**鋼化玻璃**上。在maimai選歌完開始前進入設定的頁面中，其中一個主題叫做sensor，就是透過螢幕來將這些透明的區塊具象出來(擷取自 https://maimai.fandom.com/zh/wiki/%E9%81%8A%E6%88%B2%E7%B0%A1%E4%BB%8B?variant=zh-hans)

![maimai 設定頁面中的 sensor 主題，顯示觸控區塊](assets/sensor_theme.webp)大概就像這樣

所以，maimai的螢幕本質上是背面用普通螢幕，正面再放玻璃和感測器來抓你的觸控動作

那麼這塊玻璃和ITO又是怎麼讀到觸碰的訊號呢? 本質是透過"RC濾波電路"的原理來實現，當手碰在背面貼著ITO的玻璃面上，會產生一個電容，ITO透過銅線連接在mpr121上，這個mpr121模組會不斷向ITO放電，因為手的關係會讓mpr121模組接收到充放電的時間不太一樣，進而辨識出被觸碰的狀態。(我在原理這方面可能講得不太清楚，有興趣的可以上網查查)(圖片擷取自 [連結](https://www.google.com/imgres?q=rc%E6%BF%BE%E6%B3%A2%E9%9B%BB%E8%B7%AF%20%E8%A7%B8%E6%8E%A7&imgurl=https%3A%2F%2Fmiro.medium.com%2Fv2%2Fresize%3Afit%3A774%2F1*9osAFOQgx3IhJ586Dg0XQA.png&imgrefurl=https%3A%2F%2Fmedium.com%2F%40acamvproducingstudio%2Frc-%25E4%25BD%258E%25E9%2580%259A%25E6%25BF%25BE%25E6%25B3%25A2%25E9%259B%25BB%25E8%25B7%25AF%25E8%2588%2587%25E5%2585%2585%25E6%2594%25BE%25E9%259B%25BB%25E7%2589%25B9%25E6%2580%25A7%25E8%25A9%25B3%25E8%25A7%25A3-23ba8c7a9968&docid=OgYoWU5xlPDJ3M&tbnid=uf900lkKKjS_EM&vet=12ahUKEwiXnanx0KyXAxWihq8BHZF3PFkQnPAOegUIiQIQAA..i&w=387&h=182&hcb=2&ved=2ahUKEwiXnanx0KyXAxWihq8BHZF3PFkQnPAOegUIiQIQAA))
![RC 濾波電路觸控原理示意圖](assets/rc.png)

好簡而言之就是在ITO上面用膠帶黏上一根線，然後把線的另一端接到mpr121的觸控點就能用了(嗯非常之簡潔)

接下來是ITO的規格，**一定要買帶背膠**，不然聽說很難弄，大小我建議直接找上面寫一平方公尺大的，這樣剪錯了還有重作的空間，規格中還有一個"方阻(面電阻 片電阻 or sth反正就是一個歐姆/方單位的)"這個參數，我自己是挑40歐姆，聽說越高越透明，但可能靈敏度會更低，~~如果沒什麼想法就跟我買一樣的也行~~，我自己是在淘寶上隨便找了個210CNY的，含運總共約1100台幣，如果不想用這類的平台，蝦皮上也有A4的選項，但價格會高很多，需要自行斟酌。

最後說說ITO的接線方式，有兩種方法，一個是剪出小的形狀，透過0.13mm粗的漆包線來將其接到mpr121，透過砂紙磨完兩端後，一邊用透明膠帶黏在ITO上，**注意!!!膠帶面積不能太大，不然很容易出現"寄生電容"導致按下的狀態會壞掉**，另一端則焊接到mpr121上，優點是方便而且很穩定，缺點就是有點醜，畢竟線不是透明的，引用一句話~~但是你在打的時候都看不清楚滑星的方向了哪有時間在乎這個~~。

另一種方式是將ITO剪出自帶導線的形狀，引到外面後就可以一樣用銅箔膠帶加上任意導線焊接到mpr121上，優點是螢幕看起來會很乾淨，但如果導線稍微剪歪了，跟其他區塊重疊，或是剪太細、中間不小心劃傷造成斷路，這區塊可能會非常不穩定。 我原本是用這個方法，但就是因為B區跟E區太難搞，最後把引出的導線全部剪掉改成漆包線了qq。

ITO其實還有另外兩種方式，一個是蝕刻，利用一些化學工藝直接弄到玻璃上，理論上會完全沒痕跡，如果預算足夠充足可以直接去網路上找代工(印象中一塊這樣的玻璃不含運5000台幣)，另一種是我自己想像的，把超大片的ITO直接貼到玻璃上，再用刀具分割區塊，這樣理論上就不會有剛剛剪不準的問題了，但是實務操作上很容易有氣泡，不好處理，如果有三四個人一起弄可以幫我試試看。

ITO剪的形狀[在這(Syndric/maimai-controller-fullsize)](https://github.com/Syndric/maimai-controller-fullsize/blob/12a12d8874ba55f19a7bfe75ee2fa238b4887faa/dxf/mai_pico_a4.zip)，用多張A4的方式把每個形狀都印出來後剪下，把ITO放在上面照著剪就行

(Btw以上內容我在撰寫這篇的當下才發現沒有單獨拍過照，請大家就從我給的參考資料中尋找吧，尤其是[這篇(NaiXi2233/dkmaiproj)](https://github.com/NaiXi2233/dkmaiproj/blob/main/tn/2.md)比我講的詳細100倍，也有更多防採雷的內容)

## 外框
外框有兩種做法，一種是自己3D列印，但我不會建模，所以你們可能要去找找其他資源。第二種就是買現成的，雖然真的很貴，但就圖個方便。八個按鍵720CNY，還要加上八個裝飾框180CNY，這應該算基本，可能還是廉價的版本，聽說有種兔鍵手感更好，但平均一顆七百多台幣我真的買不下去。

說說按鍵的原理，它很像是光軸，裡面有個金屬彈片，在按壓時會彎曲，放開後彈回，在按下去時彈片本身會有一個地方遮住光眼，可以想像那邊是一個雷射(紅外線)一直照著一個人的眼睛(光眼)，當兩者之間被遮擋時，那個人就會有反應，傳回一個被按下的訊號(高電位)

一顆按鍵本身有三個接腳，分別是VCC、GND、OUTPUT，其中VCC跟GND是用來提供紅外線和光眼電力，並且OUTPUT會根據接收到的信號(按下和放開)改變狀態

還有，這個按鍵的訊號必須經過上拉電阻，具體原理有點忘了，但總之OUTPUT前面會需要串接一顆約5.1K的電阻來穩定這個訊號，大概像是這樣:
```
3.3V->5.1k->output->(button IC)->GND
        |-GPIO
```

來說個獵奇的東西，你可能不能相信線上的顏色，先說你買到按鍵後拿到一條從按鍵接出來的線，你會需要另外買別的線再次接上這個線來拉到電路板上，雖然說這個線本身用的接頭都是有方向性的，但~~不知道哪個神經病做的~~，把三個Pin用紅黑黃的順序排列線，可是光眼是GND OUTPUT VCC，這個順序不一樣，就會導致線上的紅色可能其實是GND，總之這要特別再留意，可以用電表二極體擋位測測看，先選兩個腳位假設是VCC GND，通電後再用電表找假設GND跟另外OUTPUT的腳位，按下按鈕要是電表有叫就可以確認位置了。Btw我的OUTPUT是中間，說不定你們買到的也是。

然後是按鍵的燈光，我買的按鍵沒有內建，要自己買WS2812燈條，密度我是用一公尺60，一個按鍵4顆，但實際上一公尺應該15或30就夠了，一個按鍵抓一到兩顆，不然功耗可能會高到需要額外供電(像我)，當然多幾顆也會比較亮，可以自行斟酌，LED數量就是8*1~4(看你要放多少)

講到LED順便提一下，Aime掃描跟機台本身也是有燈光的，但我這次沒有做

回到按鍵本身，除了有光眼、彈片，還有底座、上蓋、按鈕、軸等材料，我想講的是底座跟上蓋，除了上蓋其他的零件都是連在底座上的，底座上有四個洞可以用螺絲鎖在前面板上，而上蓋則是用另外四顆小螺絲鎖在底座上，基本上要維修按鍵不太需要動到底座，只要把上蓋拿起即可。

燈條要先拆開按鍵黏上去，並且焊接線上去，建議像我一樣找八組公頭+母頭的線，WS2812的Data腳會有IN跟OUT兩個方向，可能就OUT都焊公頭的線，IN都焊母頭的線，等按鍵都裝上去面板後就可以串連起來了

## 前面板
這是要支撐一堆東西的一層，中間要開圓形的洞，正面要鑽孔安裝按鍵，背面要挖凹槽嵌入玻璃板，邊邊要鎖在支架上，看過的做法有用鋁板，好像有塑膠類的板(不確定，感覺會被打爛)，還有木板(夾板)，我選擇的方案

木板算是種很方便的方案，直接去台北市中正區(還萬華區)西藏路找那個木工店就可以訂做了，汀洲路也有，反正就隨便找，把木材切成正方形，中間弄出兩個圓對他們來說不難，但我還是花了2000塊台幣，因為我不太熟木工相關的知識，有了解的可以在跟我說說這樣算不算合理

在訂製前要先了解到這整體的尺寸，內框螢幕的直徑是52cm，如果是用圓形的玻璃，大概要抓外圈各+3cm的空間放進夾板的凹槽中，所以我是訂製一塊**直徑580mm、5mm厚的圓形鋼化玻璃**，夾板上則是**在正中間**挖出**直徑583mm、下凹5.5mm的凹槽**以及**直徑520mm的洞**，同時外框本身寬度是70cm，因此我訂製的是80x80cm、厚1.7cm的正方形夾板(要更小也可以，但空間會稍緊，然後我個人認為夾板可以薄一點，這個厚度會讓外框跟螢幕垂直間距明顯增加，更容易讓手撞到外框邊邊，但這厚度要改，也得記得改螺絲的長度)

![裁切完成的夾板前面板](assets/wood.jpg) 切成這個樣子

接下來是各種東西要怎麼固定在上面，我的按鍵是用木材自攻螺絲，前面會有尖角的那種，直接把按鍵鎖進木板中，反正按鍵底座是不會需要拆掉的。裝飾框則是先鑽出洞(每個按鍵底座的側邊正中間都會有一個圓型的半圓，就是預留空間給裝飾框的螺絲，照這個圓的位置鑽下去)，用那種螺絲套筒按進去，再把裝飾框用套筒對應的螺絲鎖上。

關於所謂的螺絲套筒，我原本預期是類似銅柱的東西，可以自攻進木板並自帶螺紋，但我真找不到這種東西，或者都太細了(都是M3，但裝飾框洞的大小是M5)，最後就是在小北百貨找了個看起來很像的東西裝上去，但那個套筒的設計，也讓我無法再把按鍵的上蓋打開，不算是個好設計。

## 支架
支架要支撐整個裝置，我基本上是直接抄[這個 對就是前面那個3D建模](https://cad.onshape.com/documents/0de9fedbf647e37c2995b7f4/w/1d45f7dfa4ad59765e1a4e80/e/e38d63b666de5499eb63b129)，使用2020鋁擠(長寬都是20mm的意思)，它是一種很便宜的材料，每10公分大概15塊台幣，我總共使用1080公分，鋁擠的特性就是四面會有凹槽可以進行固定，具體方法是使用鋁擠專用的先置或後置螺母，還有L型腳件

先科普一下這螺母是什麼: 先置的大小只能從側邊放入凹槽，比較穩；後置則較小，可以在側邊已經封閉的情況下放入，放入後透過螺絲轉動其方向以達到卡住的目的

L型腳件則是一個L字型，形狀可以剛好插進鋁擠，在透過一種小螺絲(止付螺絲)將它鎖死在鋁擠上，可以讓兩跟鋁擠以直角固定

我還有用到活動絞鍊，用來將整體做出斜撐，這個在原本那個Google文件裡是使用3D列印客製的，我這個則是現成的(但我從蝦皮訂，甚至比同天淘寶訂的還晚一天到= =)，一邊透過絲攻在鋁擠側邊的洞鑽出螺紋後鎖上去，另一邊則使用先置螺母+螺絲鎖在鋁擠表面

## 電路和韌體
這個項目是基於mai_pico來製作，首先最主要用到的就是Raspberry Pi Pico作為驅動整個裝置的微控制器，需要用到的電路並不難，但很多。

觸控部分使用的是前面有提到的mpr121，也算是這類機台專案觸控常用的方案，使用I2C通訊，一個晶片上具備12個觸控點，可以焊接線到銅箔或ITO來偵測觸控，說到銅箔，建議嚴肅參考我的另一個專案[ESP32-Chunithm-Controller🤓☝️](https://github.com/samuelhsieh0829/esp32-chunithm-controller/blob/main/README-TW.md)，話說回來聽說這東西良率不高，雖然我沒遇到這情況，但畢竟一個只要台幣36塊，建議一次多買幾顆備用，我自己一次是買五顆。

原mai_pico是使用三顆mpr121，maimai上的區域共34個，mpr121三個就是12*3=36便足夠，但聽說四個會比較穩定，而且也比較好分區，因此最後我決定去修改mai_pico的程式來支援我的4個mpr121，並弄出了自己的fork (我先在這裡承認，程式全是gpt-5.6-sol生的，壞掉顯然不是我的問題😯)

說到我弄出了一個fork，我還順便叫AI幫我搞了個調適介面，蠻方便的，可以用GUI修改每個區塊的觸發值以及查看所有區塊觸控的狀態，可以去參考[這個(samuelhsieh0829/mai_pico)](https://github.com/samuelhsieh0829/mai_pico)

話說回電路，我看到的所有教學都建議mpr121這種高速傳送資料的要使用抗干擾的線材，老實說我也不知道這差多少，但畢竟線要繞一整圈，總長應該兩公尺多，這樣的設計也算合理，所以我也在光華買了個三公尺的"麥克風線"，基本上就找裡面有四條線，旁邊又有鐵絲棉絮編織網+超厚橡膠皮的線就對了，或是也可以去尋找"屏蔽線"，(蝦皮上不少，但都是較長備貨，拉完了)，但不得不說這真的挺貴，我買7公尺左右的4Pin線花了台幣140，這屏蔽線三公尺就要台幣240，真的嚇哭了，而且這用起來其實挺麻煩的。。。算了先停止抱怨，mpr121還有一個所有教學都會強調的點，**背後addr隱藏的線要割掉**，因為mpr121上I2C的定址是根據addr腳位短接到的腳位決定，**預設是GND**，如果沒有割掉會變成**每一個mpr使用相同位址，一定會衝突**，因此建議每一個mpr121拿到後預先處理完，在手動跳線來決定每一顆使用的位址

接下來是按鍵們，按鍵包含那八顆按鍵，以及四顆額外按鍵，分別是: 機台中間的1P按鍵、投幣按紐(是的如果你有看過Y19玩10次換1次就是打開機台按一下按紐來幫你開一道)、Test跟Service(maimai的設定介面)，八顆按鍵是固定使用VCC、OUTPUT、GND的組合，基本上就是5V並聯8顆220歐姆電阻，每顆電阻再分別連上8個按鍵的VCC，然後把3.3V串聯上八顆5.1k歐姆電阻後，並聯到共8個GPIO以及8個OUTPUT上，最後全部GND並連回Pi Pico上。另外四顆按鍵我選用的是之前組鍵盤剩下的機械軸，這比較簡單，兩個Pin任一邊接GND，另一個接GPIO即可，這裡是使用到Pi Pico內建的上拉電阻(程式內使用INPUT_PULLUP定義的腳位)

然後是WS2812，前面有講到每一個按鍵會串在一起，理論上你可以串成一個圈，大概就像這樣(擷取自 [連結](https://memeprod.ap-south-1.linodeobjects.com/user-template/b4796eabe6cbdb1e4914edace86a69ec.png)): ![WS2812 燈條串成一圈的示意圖](assets/wtfisthis.jpe)

嗯很明顯你會需要把一個IN跟OUT分開，我自己是用4號鍵作為IN，一路3->2->1->8->...->5這樣，而四號的IN口分為5V、D、GND，D會接在Pico上當作資料輸入，GND也會接到Pico上的GND來讓D形成迴路，而5V你當然也可以接在Pico上的VCC，但為了避免讓Pico的電壓不足，我選擇把VCC跟GND額外接出到一組排針上，在透過DC電源母座提供外部電源輸入

剩下一些要注意的就是:
- 不要用杜邦，之前中二我用的體驗就不太好，有文章也說不要
- 有力氣去設計個PCB吧，手搓電路板好累，畢竟8顆按鍵，每一種電路要做8次很可怕
- Pi Pico旁加一個0.1uf跟一個10uf的電容，聽說很有用

## 統整

### 韌體操作步驟

#### 0. 事前準備
- Raspberry Pi Pico，以及一條**能傳資料**的USB線(只能充電的線會讓電腦完全看不到Pico)
- Chrome或Edge瀏覽器，設定頁是靠Web Serial連線的，Firefox和Safari不支援
- Node.js(裝好會附帶npm)，到 https://nodejs.org 下載。不會裝的話叫Codex或Claude Code幫你裝:D
- Git(可選)，沒有的話可以直接在GitHub上按Download ZIP
- 硬體要先確認的地方:
  - 所有mpr121的SDA接GPIO6、SCL接GPIO7，WS2812的資料線接GPIO13
  - 外框按鍵用的GPIO只能是`0 1 2 3 4 5 8 9 10 11 12 14`，其中6、7給I2C，13給燈，韌體不會讓你選到別的
  - **四顆mpr121的I2C位址不能重複**，韌體固定找下面這四個位址:

|mpr121|ADDR腳接到|I2C位址|設定頁上的編號|
|---|---|---|---|
|第1顆|GND|0x5A|MPR 0|
|第2顆|3.3V|0x5B|MPR 1|
|第3顆|SDA|0x5C|MPR 2|
|第4顆|SCL|0x5D|MPR 3|

mpr121模組出廠時ADDR和GND之間有一條細細的預設連線，第2~4顆一定要先用美工刀割斷，再依照上表把ADDR焊線到對應的腳位，第1顆保持接GND就好。這個「第幾顆」只是位址的編號，不代表它一定要接在ITO的哪一邊，每個ITO區塊接在哪顆的哪個電極都可以，待會在設定頁分配就行。

#### 1. 取得程式
```bash
git clone https://github.com/samuelhsieh0829/mai_pico.git
```
或在GitHub頁面按Code → Download ZIP後解壓縮。資料夾裡面會用到的東西:

|路徑|用途|
|---|---|

|`configurator/`|網頁設定器|
|`firmware/mai_pico-20260905-inputfix1.uf2`、`inputfix2.uf2`|9/5的歷史版本，另附`.sha256`校驗檔|

#### 2. 燒錄韌體
1. 把Pico的USB拔掉
2. **按住Pico上的BOOTSEL按鈕不放**，同時把USB插到電腦
3. 電腦會跳出一個叫`RPI-RP2`的隨身碟，這時可以放開按鈕
4. 把`firmware/mai_pico.uf2`拖進這個隨身碟
5. 複製完成後Pico會自動重開，那個隨身碟會消失，這就代表成功了。不用等它顯示完成，也不用手動退出

之後如果要更新韌體，可以不用再按BOOTSEL，在設定頁的「進階終端」(或任何序列埠終端機)輸入`update`，Pico就會自己重開進入`RPI-RP2`模式，再把新的UF2拖進去。

換版本後如果行為很奇怪，可能是舊設定格式和新韌體不合，可以輸入`factory`重置為預設值，然後重新插拔。**但這會清掉全部自訂設定**，所以先在設定頁按「下載 JSON」備份。

#### 3. 啟動設定頁
設定頁在`configurator`資料夾裡，是在自己電腦上跑的網頁，不需要網路也不需要後端。

**第一次使用**要先安裝套件，開終端機(PowerShell或cmd)輸入:
```bash
cd "C:\{你的檔案路徑}\mai_pico\configurator"
npm install
```
安裝完成後，**Windows可以直接雙擊`configurator\start-local.cmd`**啟動，它會在`http://127.0.0.1:5173/`開一個本機網站。想自己用指令啟動的話:
```bash
npm run dev
```
然後用Chrome或Edge開啟 http://127.0.0.1:5173/

注意事項:
- 啟動後那個終端機視窗要**一直開著**，關掉網站就停了
- 如果出現5173埠被佔用，代表你可能已經開了一個，用那個就好，或是先把舊的關掉
- 如果PowerShell跳出「無法載入npm.ps1，因為這個系統上已停用指令碼執行」，把指令裡的`npm`改成`npm.cmd`即可，`start-local.cmd`就是這樣處理的

#### 4. 連線
1. 確定Pico已經插上電腦，且沒有其他程式(例如別的序列埠終端機)佔用它的COM埠
2. 按設定頁上方的「連接 Command Line Port」
3. 瀏覽器會跳出一個選擇序列埠的視窗。這個韌體會同時產生**四個COM埠**(Command Line、Touch、LED、AIME)，視窗裡每個埠旁邊會顯示名稱，請選**Command Line Port**
4. 選錯的話設定頁會因為收不到`cfg info`的回應而連線失敗，換一個重選即可。不確定哪個是哪個的話，可以用任何序列埠終端機連其中一個輸入`whoami`，Command Line、Touch、LED三個埠都會回報自己的身分
5. 如果視窗是空的，按「顯示所有通訊埠」取消過濾再選。還是空的就換Edge試試，用來分辨是Chrome的問題還是Windows沒認到裝置

連線成功後右上方會顯示「已連線」，右邊狀態欄的**MPR121應該顯示`4 / 4 ONLINE`，Sensor mask是`0x0f`**。如果顯示CHECK或其他數值，代表有mpr121沒被偵測到，回頭檢查那顆的I2C接線、SDA/SCL、電源，以及ADDR有沒有照上面的表接。

#### 5. 即時狀態頁(確認有沒有接對)
連線後預設就是「即時狀態」頁，這裡會以每秒25次的頻率顯示全部**34個觸控區塊**和**12顆按鍵**目前的狀態。

- 逐一摸玻璃上每個ITO區塊，看畫面上亮的是不是同一個區塊
- 勾選「顯示 Δ／目前門檻」可以看每個區塊的讀數(Δ = baseline − filtered，被摸時會升高)，用來判斷哪邊反應太小或亂跳
- 逐一按每顆外框按鍵，以及1P、投幣、Test、Service，看畫面亮的是不是對的
- 這個頁面只是觀察，不會暫停遊戲的輸入、AIME或燈光，開著玩也可以

剛刷好的韌體是出廠預設，只有三顆mpr121有對應區塊、第四顆全部沒有對應，所以**用四顆的話一定會有一堆區塊是錯的**，這是正常的，下一步就是來改它。

#### 6. 分配設定頁(最重要的一步)
切到「分配設定」頁，這裡的欄位顯示的是目前存在Pico Flash裡的值，**所有修改都只是畫面上的草稿**，按「全部保存」才會寫進去。右上角會顯示有幾筆尚未保存的修改。

**觸控分配(34個區塊)**，每個區塊有這幾個欄位:
- **MPR**: 0~3，也就是這個區塊接在第幾顆mpr121(對應上面位址表的編號)
- **ID**: 0~11，接在那顆的第幾個電極(mpr121上標示的ELE0~ELE11)
- **按下 Δ≥** 與 **放開 Δ<**: 這個區塊的觸發門檻與放開門檻。被摸到時Δ超過「按下」門檻就算按下，要降到「放開」門檻以下才算放開。中間留一段空間是為了避免在門檻邊緣一直抖動
- 如果你選到的MPR+ID已經被別的區塊用掉，設定頁會自動把兩邊**互換**，所以草稿永遠是一對一的，不會有兩個區塊共用一個電極

怎麼知道哪個ITO區塊接在哪個電極? 有兩種方法:
1. 照你焊線時的紀錄直接填
2. 到「進階終端」輸入`touch`，**一隻手摸住某個ITO區塊不放，另一隻手按送出**(或請人幫你按)，它會回報被觸發的電極，例如`Touched: E3 (Sensor 0, Electrode 1, press >= ..., release < ...)`。前面的區塊名稱(這裡的E3)是目前還沒改過的舊分配，不用管它，只看後面的Sensor和Electrode。注意!這裡顯示的`Electrode`是**從1開始數**，而設定頁的ID和`touch`設定指令都是**從0開始數**，所以Sensor 0、Electrode 1就是MPR 0、ID 0。接著把你實際摸的那個區塊(例如A1)分配到那組MPR+ID即可

我的分法是依編號1,2 / 3,4 / 5,6 / 7,8分別接到四顆mpr121，所以A1、B1、A2、B2…這些依序填進去就好。另外，`raw`指令可以一次列出34個區塊各自的MPR:電極、讀數與門檻，對照用很方便。

*本人補充一下，在一開始將ITO接線到mpr121時你就已經知道大概把哪些區塊放到哪顆了，假設我A1~2,B1~2, C1, D1~2, E1~2都接在Sensor 0，就可以先把全部區塊依照這樣的方式把Sensor都選好，接下來就只需要改具體電極，會方便很多*

**按鍵分配(12顆)**，包含8顆外框按鍵，加上Test、Service、Navigate(也就是1P選擇鍵)、Coin(投幣):
- **GPIO**: 只列出韌體允許的腳位，選到已被占用的也會互換
- **Active level**: 按下時腳位是LOW還是HIGH。韌體預設是LOW(內部上拉，按下時接到GND)，像我另外四顆機械軸的功能鍵就是這種。外框的光電按鍵是否反相要看你的接法，**按一顆看即時狀態頁，如果沒按就亮著、按了反而滅掉，就是極性反了**，把Active level切換過去。這個選項是一組一起切的(外框八顆是一組，四顆功能鍵是另一組)

預設的GPIO對照是外框B1~B8為`1 0 4 5 8 9 3 2`、Test 12、Service 11、Navigate 10、Coin 14，不用照這個，插哪個腳都行，只要在這份清單裡，並在這裡改成你實際插的。

**保存**: 全部改完按下方的「全部保存」。它會先暫停即時監看，把34個區塊和12顆按鍵的設定當作一筆交易寫入Flash，再讀回來比對，確認一致才算成功，然後自動恢復監看。保存期間遊戲輸入會短暫暫停，這是正常的。如果畫面上有被標示出來的錯誤(例如門檻設定不合理)，要先修正才能保存。

另外還有:
- 「放棄修改」: 丟掉草稿，回到裝置目前的設定
- 「下載 JSON」: 把目前的設定存成備份檔(`mai-pico-hardware-profile`格式)
- 「匯入 JSON」: 載入備份檔成為草稿，仍要按「全部保存」才會寫入。**調到滿意後強烈建議下載一份JSON**，之後`factory`、換韌體或換板子都能直接匯回來

重要提醒: 還沒保存就關掉網頁或拔掉USB，草稿會全部消失。

#### 7. 燈光和其他設定(進階終端)
這些是用指令設定的，到設定頁的「進階終端」輸入，或是用 https://googlechromelabs.github.io/serial-terminal/ 這種網頁序列埠終端機連Command Line Port都可以。輸入`?`會列出全部指令。

以我的燈光為例(亮度`128`只是舉例，依你的電源和喜好調整):
```
rgb 4 0 0
level 128
save
```
- `rgb <每顆按鍵燈數> <每個機台燈節點燈數> <banner燈數>`: 我一顆按鍵4顆燈，沒有裝機台燈和banner，所以是`rgb 4 0 0`。燈數填0代表忽略這個節點。Aime的燈固定16顆，不能改，沒裝讀卡機也沒關係
- `level <0~255>`: 亮度。燈很多或是電源不夠力的時候調低一點
- 燈鏈的順序(4→3→2→1→8→7→6→5)是寫在韌體原始碼`firmware/src/board_defs.h`裡的`RGB_BUTTON_MAP`，**不能用指令改**。我的串法剛好跟預設一樣，所以不用動。如果你的串法不一樣，要改這個陣列後自己重新編譯韌體
- `save`: 多數指令改完會在幾秒後自動儲存，但保險起見改完輸入一次`save`立刻寫入

其他常用指令:

|指令|用途|
|---|---|
|`display [rgb\|sense\|hid\|gpio\|touch\|aime\|tweak]`|顯示目前設定，不接參數就是全部|
|`touch`|不加參數 = 偵測目前被摸的區塊及其電極|
|`touch <sensor 0~3> <電極 0~11> <區塊名>`|直接指令指定映射，例如`touch 1 9 E6`，區塊名填`XX`代表不連接|
|`gpio main <8個GPIO>`|設定八顆外框按鍵，例如`gpio main 1 0 4 5 8 9 3 2`|
|`gpio <test\|service\|navigate\|coin> <GPIO>`|設定單顆功能鍵|
|`gpio reset`|GPIO全部恢復預設|
|`tweak main_button_active_high <on\|off>`|外框按鍵極性(on = 按下為HIGH)|
|`tweak aux_button_active_high <on\|off>`|功能鍵極性|
|`hid <io4\|key1\|key2\|off>`|按鍵傳給電腦的方式，見下方|
|`sense [區塊\|*] <+\|-\|0>`|靈敏度微調，沒指定區塊是全域|
|`filter <first> <second> [interval]`|mpr121雜訊濾波參數|
|`debounce <touch> [release]`|觸控去彈跳，0~7|
|`raw`|列出每個區塊的讀數、基準值、Δ和門檻|
|`stat [reset]`|觸控統計|
|`cfg info`|顯示韌體版本與裝置資訊|
|`cfg diag`|輸出診斷資料，排查問題時用|
|`whoami`|讓Command Line、Touch、LED三個埠回報自己是誰|
|`aime mode <0\|1>`、`aime virtual <on\|off>`|Aime讀卡機設定(本專案沒裝)|
|`update`|重開進入`RPI-RP2`模式，用來更新韌體|
|`factory`|恢復出廠設定(會清掉所有自訂內容)|

`hid`的模式: 預設`io4`，以IO4的方式把按鍵送給遊戲。`key1`是用鍵盤輸入，外框八顆是`W E D C X Z A Q`、選擇是`3`；`key2`同樣是鍵盤但用數字鍵盤，外框八顆是`8 9 6 3 2 1 4 7`、選擇是`*`；兩種鍵盤模式都有`F1`=Test、`F2`=Service、`F3`=Coin。`off`則是不送出按鍵。

#### 8. 驗收
1. 重新插拔USB，**手離開面板等一秒左右**，讓mpr121做完初始化與基準校正。如果開機的時候手正貼在玻璃上，基準會被校正錯，之後整片都會怪怪的
2. 開即時狀態頁，34個區塊每個都摸一遍、12顆按鍵每個都按一遍，確認每個都對
3. 摸住一個區塊不放，看它會不會維持按下直到放手；放手之後有沒有確實回到未按下。如果放手後還是顯示按下，多半是前面說的寄生電容問題(多餘的ITO、膠帶面積太大)
4. 在進階終端輸入`cfg info`確認韌體版本，`cfg diag`保留一份當作基準，之後如果出問題可以對照
5. 如果觸控整片怪怪的(例如開機時手有碰到)，**先把手移開**，再**長按Coin鍵2秒**，會重新初始化觸控並校正基準
6. 接上遊戲連續玩一陣子，看看有沒有漏按、自動連點或卡住

遊戲端的部分，如果你用的是Sinmai，記得`mai2.ini`裡`[AM]`底下的`DummyTouchPanel`要設成`0`(使用實體觸控面板)，依照`firmware/INPUT_FIX2_NOTES.md`的分析，設成`1`(假的觸控面板模式)時遊戲會把觸控狀態和計數另外處理，可能出現持續按住被清掉、連點的現象。改之前先備份檔案，改完要完整退出遊戲再重開才會生效。`mai_pico/firmware`資料夾裡有附一支`apply_inputfix2_game.py`可以自動備份並只改這一個值，用法是
```bash
python firmware\apply_inputfix2_game.py --ini "D:\你的遊戲路徑\Package\mai2.ini"
```
加上`--verify-only`則只檢查不修改。另外，Touch和LED各自是不同的COM埠，遊戲啟動器那邊要填的COM編號，請用`whoami`確認哪個埠是哪個。

診斷細節(`cfg diag`每個欄位的意思、怎麼判斷是晶片、韌體還是USB層的問題)寫在mai_pico裡的`firmware/INPUT_FIX2_NOTES.md`，有需要的人再去看。

#### 9. (選用)自己重新編譯韌體
一般來說直接用現成的UF2就好，只有要改預設值(例如`board_defs.h`裡的`BUTTON_DEF`按鍵GPIO、`TOUCH_MAP`觸控預設映射、`RGB_BUTTON_MAP`燈鏈順序)才需要自己編譯。需要安裝Raspberry Pi Pico SDK、Arm GNU embedded toolchain、CMake，我編譯時用的是Pico SDK 2.3.0、Arm GNU Toolchain 12.2.1、目標板是RP2040。接著在`mai_pico`資料夾執行:
```bash
git submodule update --init --recursive
cmake -S firmware -B firmware/build -DPICO_SDK_PATH=<你的pico-sdk路徑>
cmake --build firmware/build
```
編譯完成會得到新的`mai_pico.uf2`，刷法和上面一樣。設定頁本身的測試與打包可以在`configurator`資料夾執行`npm test`和`npm run build`。

### 實際調試遇到的問題
好接下來這裡就是我寫的了

照著上面的流程把韌體和設定頁弄好之後，我很快就發現問題，很多ITO會在未觸碰的情況下觸發，還有按下去反應很小，甚至根本沒反應，這裡基本上已經發現到了ITO引出的問題: 這引出條可能電阻太高了(剪太細，R=kL/A，很簡單的道理，截面積越小、長度越長，電阻越高，電阻太高可能就直接不通了)，因此我也開始把一些引出條剪掉，改成使用漆包線+透明膠帶黏在ITO上，另外一端焊接到原本黏ITO引出用的銅箔上，利用銅導線能很大程度的解決這個問題

## 2026/9/4 內圈修復、裝飾框安裝、支架安裝
很可惜我沒有拍到裝飾框安裝的部分，但總之當天我約plumtofu來幫我弄這部分的東西，基本上外框都安裝好後，每一個按鍵旁邊的半圓可以直接鑽孔下去，安裝前面有買的螺絲套筒，這種套筒的側邊會有紋路，讓套筒本身死死的咬在木頭上，把套筒按進去後，裝飾蓋蓋上，將螺絲對準裝飾蓋底下的套筒鎖上就完成了

到此為止整個控制器算是做好了，但在安裝到支架前，還需要把觸控調整好，一旦將前面板安裝到支架就很難再去動這部份了

9/3我有先筆記過每一個ITO的情況，有些是碰上去反應小，有些數字會隨機抖動，有些則完全卡死，還有一些碰到一個會動兩個，以下是我在當下排查完後得出的結論:
- 碰到一個動兩個其實就是ITO引線重疊了，這就是我的手藝太答辯了，剪掉其中一個改用漆包線，就這樣~~或是全剪了，反正漆包線比較穩~~
- 反應小是因為電阻太高了，這種就直接把ITO引出剪掉，**一定要剪掉，待會講為什麼**，改成用漆包線黏上去+焊接
- 隨機抖動基本上就是斷路了，這時候請嘗試觸碰一下這個區塊連接到mpr121的IO處，如果數字瞬間變大就代表是引出那邊電阻真的太高，這就是用上面一樣的解決方式
- 如果數字卡死，且觸碰mpr121上面的電極完全沒反應，那有一種很常見的情況是**他跟旁邊的電極短路了**，我當下就有好幾個區塊長這樣，以為是他壞掉了，就決定換一個電極用(當然不排除有可能這種壞掉情況真實存在)，但我一把線解焊馬上就好了，所以可以判斷是電極處的線不小心碰到隔壁而造成的異常

總之經過這一輪修復都好得差不多了...嗎? 雖然感應是感應的到了，但開始會出現摸上去放開後，電腦端顯示還是有觸碰，這其中一部份就是這導電的過程多了太多空間，導致**寄生電容**(好像是GPT說的，應該是這樣)，一個來源就是多餘的ITO，對，所以**要是沒有要用ITO當引線就把它剪掉**，另一個是**漆包線上的膠帶面積太大**，這情況就比較隨機了，因為我有一些區塊面積太大也沒事。這個後來在2026/9/18我有去做修整，將膠帶面積變小確實能有效解決90%這種問題，但依舊有些地方會隨機發生，這我就無解了，總之**使用膠帶黏漆包線要盡量減少膠帶面積**

好了到此為止控制器就真正完成了，最後一部就是把它架成真正的手台，上螢幕和支架。

木板的左、右、底共開12個洞，這個洞理論上要在距離邊邊1cm為中心，一邊分四等分，這些洞挖穿後將支架平躺在地板，這三個邊要各放入四顆先置螺母(如果之前已經裝好了的話，unlucky bro你底下的邊應該被擋住了要拆開來放先置進去ww，或是有後置螺母的話或許能用)，大概放定位後把螺絲從木板上面鎖進去，我自己是沒全部鎖，因為對準螺母真的太麻煩了，而且不知哪來的公差導致整體其實有點歪掉無法對準，最後我只有弄好9顆，至少現在放一個月還沒炸應該沒事(?)

目前的進度是: 可以直立起來了，其實這樣應該就可以玩了，但10cm的站立其實不太穩，因此還需上斜撐

## 2026/9/5 斜撐安裝、完成
最後的最後是要將背面的支撐和底座安裝上去，活動絞鍊可以被分成兩截，一截安裝在鋁擠的側面(那個2*2cm的截面)，一截用先置螺母加螺絲固定到鋁擠的凹槽，要安裝到鋁擠側面，首先需要將上面的圓洞做出螺絲紋路，這就需要用到M5絲攻，我買到的有三個大小，似乎是不同階段用到的不一樣，會要先開個最大的再慢慢變細，這我不是很懂，有經驗的人或許能幫我補充，總之用法就是把絲攻安裝到電鑽上，再洞上滴一點潤滑油後鑽一下退出一下，這樣深一點出來一點，深一點出來一點，一直進出進出~~好色喔~~，慢慢把紋路鑽進去，再用更細的繼續重複，最後嘗試用M5螺絲，只要能正常鎖進去就可以了。需要絲攻的地方有: 兩跟44cm的斜撐支架、支架背後的兩跟80cm底部。

完成絲攻後，先拿出最後剩下的兩根44cm當底座，兩個各選擇其中一面各放入兩個**M6先置螺母**，接著用保護套將兩邊套上，把六個絞鍊拆開，其中四個以相同方向(朝向與鋁擠平行)安裝到底座上(大孔記得朝外，方便晚點使用扳手鎖上)，這一步驟重複在背後支架80cm上做一次但先不用鎖死。

44cm的斜撐支架要先跟最後一個76cm合在一起，怎麼組參考一下設計圖，不想多贅述

最後這部需要兩個人一起，要把所有活動絞鍊組起來，需要一個人負責搬著支架帶前面板，另一個人把六個絞鍊鎖上，當然如果真做到這一部，應該還有別的比較輕鬆的方式可以把這部做好，我有點忘記當時是怎麼做的了，反正跟馬麻合作，轉轉轉就全部弄好了。

到這裡，這個手台就算是全部完成啦🥳，給自己一個掌聲鼓勵鼓勵，能做到這樣真的不容易，~~然後會馬上意識到這東西沒個兩個人真的搬不動~~

# 總結
做完這整個裝置，我有蠻多感想的

首先是自己採到的坑(或是值得再次重點提醒的地方)，直接整理成一個清單:

- ITO引出條一開始就直接用漆包線 (一樣你對自己手工有自信再嘗試，但自信有時會騙人)
- 膠帶面積一定要小
- mpr121的ADD線要割 (這個大家都會講)
- 按鍵線色不能信
- 任何接線保護一定要用絕緣膠帶，**尤其是不要以為銅箔膠帶能抗干擾就當作是絕緣**
- 1.25mm接頭線太細，不適合用來給WS2812這種高電流需求的裝置
- 夾板可以比1.7cm再更薄
- 螺絲套筒會讓上蓋打不開，要找其他類似銅柱的方案來固定裝飾蓋
- 支架先組好會擋住底邊裝螺母，有些地方知道會被擋住就要預先把東西放好
